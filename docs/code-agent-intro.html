01 · Overview

一个 可自我进化的 编码代理

CodeAgent 不是一个"用完即弃"的脚本，而是一套可扩展的代理框架：它以 VS Code 的 contribution / service 分层为骨架，把「工具执行、上下文管理、技能系统、记忆系统、模型路由、基准测试」做成一个个可插拔模块 —— 既能当日常编码助手，也能作为团队内部 Agent 基础设施被反复打磨。

04 · Execution

一次任务如何被完成 —— 执行链路深挖

深挖 · 可跳过建议 5′配合 --stream / task log 现场对照

从命令行回车到最终交付，一条任务依次穿过 9 个阶段；每个阶段都能在仓库里找到对应模块，并在 ~/.codeagent 下留下可回放的产物。讲这一节等于把②③⑤的模块串成一条线。

1

参数解析 / 进入 REPL

带任务参数 → 单轮执行（--mode 决定 agent / plan / ask 语义，--parallel 拆并发，--resume 接上次会话）；不带参数 → 交互式 REPL（斜杠命令 + Tab 补全）。

vs-core/node-runtime/main.ts · 1,297 行
2

配置加载（三层优先级）

CLI 参数 / 环境变量 > ./config.yaml（项目级）> ~/.codeagent/config.yaml（全局）；active_profile 决定默认模型，可 --profile 随时切换。模型定义独立放在 models.json。

agentConfig.ts · 529 行
3

服务装配（vs-core DI 容器）

实例化 FileService(fs) / SearchService(ripgrep) / TerminalService(child_process) / LLM Provider / ToolRegistry / SkillsLoader / MemoryGateway。业务层只面向接口编程，换实现不动业务。

vs-core/platform + node-runtime 服务实现
4

技能与规则装配（任务级重建）

扫描 skills / rules 目录：alwaysApply 规则全量注入；技能先做 trigger 评分自动匹配（top ≤ 5），把匹配到的 SKILL.md 全文 注入系统提示词 —— 任务不同，上下文不同。

agentSkills.ts · 426 行
5

记忆召回（fail-open）

MemoryGateway.recall(task)：并行拉取 L1 原子事实检索 + L2 场景索引 + L3 人格，注入系统提示词。任何一步失败仅 console.warn，绝不阻断任务。

agentMemory.ts · 639 行
6

模型路由选择

detectScenario(prompt) → reasoning / vision / fast 三档，映射到对应模型；发生切换时打印 “switching：模型 A → 模型 B”。无路由配置则回退 active_profile。

agentModelRouter.ts · 96 行
7

ReAct 主循环（核心）

while 步数 < max：取滑动窗口上下文 → llm.complete(messages, tool schemas) → 有 tool_calls 就执行（写文件前 Checkpoint 快照；异步工具可 /btw cancel；长任务用 poll 指数退避）→ 观察结果回填 → 直到无 tool_calls 输出答案。Ask 只暴露只读工具，Plan 先生成计划。

agent.ts · 857 行 + agentContext / agentCheckpoint / agentParallel / agentPlanner
8

验证与收尾

复杂任务（refactor / migrate / 性能等）自动自我验证；简单任务直接跳过（省 ~9s）。收尾三件事：会话自动保存、任务日志落盘、L0 对话记忆捕获。

06 · Skills

Skills 体系深挖 —— 从 SKILL.md 到自动匹配

深挖 · 可跳过建议 4′提问率最高的模块

CodeAgent 的技能是 Cursor 兼容的 SKILL.md：一个技能 = 一个目录里的 SKILL.md（frontmatter + Markdown 正文）。 任务启动时按 trigger 关键词 + 名称 + 描述 自动激活并把全文注入上下文 —— 也可以让 Agent 自己维护技能库（meta-skill，skills of skills）。本机 ~/.codeagent/skills 现装 19 个技能目录。

📜 SKILL.md 契约（真实示例 · 取自已安装的 commit 技能）

---
name: commit
description: 按服务端要求生成 commit 信息并执行提交流程…
trigger:
  - commit
  - 提交
  - push
  - gerrit
  - git
  - gitee
  - jira
  - topsop
  - 静态检查
---
# 代码提交流程
当用户要在本仓提交或推送代码时，按本skill执行。

契约字段：name（kebab-case）· description（what + when）· 可选 whenToUse · trigger 关键词列表 · disable-model-invocation · user-invocable；正文以 # 开头。

🧩 自动匹配算法（agentSkills.ts · 426 行）

trigger 精确命中+10 分 / 个（最强信号）
技能名出现在任务中+15 分
描述与任务词重叠+2 分 / 词
部分包含 bonus+1 分（如“提交”↔“提交代码”）
排序取 top ≤ 5全文注入，防上下文膨胀

任务启动时预载所有技能“头部”（名称 + 描述 + triggers）供模型自匹配；命中者（top ≤ 5）把 SKILL.md 全文注入系统提示词，未命中者可运行时 code-agent --use-skill <name> 显式激活。命令行 code-agent --skills 可查看当前装了什么。

📐 Rules：alwaysApply 自动注入

.mdc 规则文件加载自 rules 目录；alwaysApply: true 的规则注入每一次对话（本 deck 的排版、Gerrit 查询、MCP 访问等约束正是这么来的）。

本机 ~/.codeagent/rules 示例作用
html-frontend-dev.mdcHTML 页面必须走 frontend-dev 流程
gerrit-query.mdcGerrit 查询优先 MCP 工具
mcp-access-policy.mdc外部服务访问策略
post-change-workflow.mdc改完代码自动重打包 / 容器 / 推送

🛠 meta-skill —— 让 Agent 自己维护技能库

skill_catalog建库前先 recall → COVERED / PARTIAL / UNRELATED
create_skill校验 canonical 契约后发布到 skillsDirs[0]
update_skill合并字段并重渲染，不覆盖已有技能
避免重复相似能力优先扩展已有技能

实现：agentSkillFactory.ts（455 行）+ tools/skillTools.ts（271 行）；prompt 端由 buildMetaSkillPromptSection 注入“技能工匠”身份段，代码源自 dsh-run2skill 移植。

07 · Memory · Router · Config

记忆 · 模型路由 · 配置三件套

深挖 · 可跳过建议 4′配合 ~/.codeagent 目录现场讲解

这三个能力让 CodeAgent 从“单机单会话的脚本”变成“团队共享的 Agent 基础设施”：记忆跨机器沉淀、模型按任务路由、一切行为可配置。

🧠 共享记忆（agentMemory.ts · 639 行）

L0 原始对话每次任务结束自动 capture
L1 原子事实偏好 / 规则 / 决策，可检索
L2 场景文件长上下文工作场景索引
L3 人格跨机器一致的行为画像

recall：任务开始前并行拉 L1+L2+L3 注入系统提示词；capture：结束后整段对话写 L0，由 hub 异步蒸馏 L0→L3。fail-open：服务不可用只告警不阻断；按 team/agent/user 隔离；基准测试用 --memory off 保证测量独立。

🔄 场景化模型路由（agentModelRouter.ts）

reasoning重构 / 迁移 / 架构 / 调试 → 强推理模型
vision截图 / 图片 / OCR → 视觉模型
fast其余简单任务 → 快模型（省成本）
切换时展示“switching：A → B”，成本透明

路由 fallback：scenario 模型 → default → active_profile。注意关键词用 debugging 而非 debug，避免把 config 里的 debug: false 误判成调试任务（这曾是 9.6s → 6.7s 的一次真实优化）。

⚙️ 配置全景（config.template.yaml）

active_profile默认模型；profiles 覆盖采样参数
model_routingscenarios → 模型映射开关
agentmax_steps / 上下文 / 超时 / temperature
skills / rules扫描目录列表
mcp_serversstdio / streamableHttp 扩展工具
memorytdai_agent_mem 端点与身份

models.json 里每个模型声明 supportsToolCall / Images / Reasoning、thinking.type、maxTokens、maxInputTokens —— 路由与 max_tokens 钳制都依赖这些能力位。

🧪 测试集 suite（5 个任务）

  • 002 读取并搜索文件
  • 003 编辑文件
  • 004 列出目录结构

12 · FAQ / 附录

高频问题与速查表

深挖 · 可跳过建议 0–5′，冷场与答疑专用

Q1 和 Cursor / Claude Code / Codex 有什么区别？

定位不同：CodeAgent 是团队内部、可插拔的 Agent 基础设施 —— VS Code 分层、技能/记忆/路由都是独立模块。基准上同模型同端点默认配置更快（快照口径见 ⑨），但各框架内部策略不同，宜以“默认配置端到端耗时”口径理解。

Q2 怎么加一个新模型 / Provider？

models.json 加一个条目（id / url / apiKey / 能力声明），config.yaml 改 active_profile 即可 —— 兼容任意 OpenAI 格式端点（DeepSeek 等）与 Anthropic / Ollama。

Q3 怎么给 CodeAgent 加一个技能？

在 skills 目录建 技能名/SKILL.md，frontmatter 写 name/description/trigger，正文写流程 —— 下一次任务自动命中；或直接让 Agent 用 meta-skill（skill_catalog → create_skill）自己写。

Q4 API key 安全吗？会不会入库？

models.json / mcp.json 只落在 ~/.codeagent（.gitignore 外）；基准 agent_bm 的 agents.json 不落 key，运行时从 models.json 解析或 BM_API_KEY 注入；记忆与 MCP 凭据走内部 Bearer token。

Q5 为什么基准里 code-agent 比别的快？

更少步骤（avg 3.6 vs 8+）与更省 token 的提示词策略：简单任务跳过自校验、工具 schema 精简、上下文压缩保守预算。注意这是默认配置口径。

Q6 断网 / 内网隔离环境能用吗？

能。单文件 agent-cli.js 零依赖直跑；模型可切 Ollama 本地；standalone-demo（MOCK_LLM=1）甚至不需要真模型，用于演示链路。

Q7 上下文太长 / 溢出怎么办？

滑动窗口 + 摘要压缩（agentContext.ts）、max_tokens 按模型上下文钳制、保守 token 预算（agentConfig agent.max_context_tokens 默认 200000）；小模型也有模型相对的溢出护栏。

Q8 什么时候用 agent / ask / plan / parallel？

agent 全自主；ask 只读问答（讲代码、查资料）；plan 先规划再执行；parallel 多个相互独立的任务并发。演示脚本 ⑩ 里每个模式都有对应 demo。

Q9 演示中途断了怎么办？

/resume 恢复最近会话；/tasks + /task <id> 看上次执行全记录；会话与任务日志都是磁盘 JSON，跨重启可回放。

Q10 下一步打算做什么？（规划中 · 非承诺）

suite 扩展复杂工程任务并统一跨 agent 的 skills/rules 口径；场景记忆在更多工作流落地；更细的 token/成本观测；VS Code 面板与远程场景。演进路线最终以 commit 为准。
